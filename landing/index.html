Le trajet du signal

Trois sauts, aucune application DJI

La caméra n'est jamais pilotée par le cloud : tout se joue entre son Bluetooth, votre réseau local et le serveur embarqué.

  1. 01

    Scan Bluetooth

    Lecture directe de BlueZ : les appareils à portée apparaissent en une seconde, les caméras DJI remontent en tête avec leur niveau de signal.

    org.bluez · D-Bus · LE

  2. 02

    Wi-Fi forcé

    djictl envoie à la caméra les identifiants de votre réseau et l'ordre de pousser vers votre machine. Plus besoin de DJI MIMO ni de routeur dédié.

    BLE → Wi-Fi 2,4 GHz

  3. 03

    Sortie RTMP

    MediaMTX reçoit le flux et l'expose en RTMP. Si OBS refuse le HEVC de la caméra, un ffmpeg supervisé republie la même scène en H.264.

    rtmp://…/live/dji-h264

Ce qu'elle fait

Un régisseur de poche

Pensée pour être ouverte cinq minutes avant le direct, sur le poste qui fait tourner OBS.

01

Scan BLE natif

BlueZ interrogé en D-Bus, sans parser la sortie d'un terminal. RSSI, nom, état d'appairage : la liste est lisible d'un coup d'œil.

02

Réseaux mémorisés

Chaque connexion enregistre le SSID et le mot de passe. Les profils se choisissent dans une liste : studio, extérieur, plateau.

03

MediaMTX embarqué

Le serveur RTMP est téléchargé dans le dossier de l'app, jamais pris dans le système : la machine peut changer, le comportement reste identique.

04

H.265 → H.264

Une bascule suffit pour que le flux passe par ffmpeg. Le H.264 republié est accepté par n'importe quelle version d'OBS.

05

État réel du flux

« Serveur lancé » ne veut pas dire « caméra connectée » : l'app interroge l'API locale et distingue les deux, avec le débit reçu et le nombre de lecteurs.

06

Diagnostics lisibles

rfkill, droits Bluetooth, port occupé, ffmpeg absent : chaque panne arrive avec sa cause et la commande qui la règle.

Latence

Réglée pour le direct, pas pour l'archive

Chaque maillon est réglé à la main pour que l'image arrive au moniteur sans traîner : sortie GOP d'une seconde, aucun frame B, timestamps réécrits à l'arrivée et paquets écrits sans tampon.

  • Timestamps à l'horloge murale. Les flux caméra et relais arrivent avec des DTS répétés : ffmpeg les réécrit à la réception, audio et vidéo restent calés, OBS ne fige plus.
  • Keyframe toutes les secondes. OBS accroche l'image tout de suite et peut couper proprement.
  • Zéro frame B, zéro lookahead. Le profil x264 zerolatency est poussé jusqu'au bout : pas de réordonnancement à la sortie.
  • Paquets écrits sans tampon. -flush_packets 1 pousse chaque frame vers MediaMTX dès qu'elle est encodée.
  • Côté OBS : tampon réseau à 0 Mo. Propriétés de la source média → « Tampon réseau » : c'est le dernier gros gisement de latence. 
ffmpeg -flags low_delay -use_wallclock_as_timestamps 1 \
  -fflags +genpts -r 30 -rtsp_transport tcp \
  -i rtsp://127.0.0.1:8554/live/dji \
  -c:v libx264 -preset veryfast -tune zerolatency \
  -g 30 -keyint_min 30 -bf 0 -fps_mode cfr \
  -b:v 6M -maxrate 6M -bufsize 6M \
  -c:a aac -b:a 128k -af aresample=async=1 \
  -flush_packets 1 -f flv \
  rtmp://127.0.0.1:1935/live/dji-h264

Installation

Trois commandes, une fenêtre

Le paquet installe le binaire et son entrée de menu. Les outils annexes se récupèrent depuis l'application.

1 · Débloquer la radio

Si le Bluetooth est coupé par le noyau, l'app le détecte et propose de le lever. En cas de refus de permission, une seule commande suffit :

sudo rfkill unblock bluetooth

2 · Installer le paquet

Le .deb contient l'application seule (3,8 Mo). Les dépendances GTK et WebKitGTK sont résolues par apt.

sudo apt install ./dji-caster_0.1.1_amd64.deb

macOS : dézippez l'archive universelle et glissez dji-caster.app dans Applications. L'app n'est pas signée : clic droit → Ouvrir au premier lancement.

3 · Lancer et scanner

Ouvrez « DJI Caster » depuis le menu, puis le bouton Installer les outils dans les réglages récupère MediaMTX et compile djictl.

dji-caster

Prérequis : Ubuntu 22.04+ / Debian 12+, un adaptateur Bluetooth, un réseau 2,4 GHz pour la caméra, ffmpeg pour la conversion H.264.
