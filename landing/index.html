Le trajet du signal

Trois sauts, aucun cloud

La caméra n'est jamais pilotée par un service distant : tout se joue entre le relais qui pousse le RTMP, votre réseau local et le serveur embarqué.

  1. 01

    Entrée RTMP

    La caméra (déjà sur le Wi-Fi) ou le relais Android pousse son flux sur la machine. MediaMTX l'accueille sur un seul chemin, sans compte ni configuration serveur.

    rtmp://…:1935/live/dji

  2. 02

    Encodage H.264 + Opus

    Un seul ffmpeg lit la source en RTSP loopback et réencode la vidéo et l'audio en une passe. Plus de copie AAC intermédiaire : le son Opus part directement de la source.

    ffmpeg · libx264 · libopus

  3. 03

    Lecture WebRTC

    MediaMTX publie une page WHEP que n'importe quel navigateur peut ouvrir. C'est la seule sortie, et la plus rapide : ~0,2–0,5 s de latence sur le réseau local.

    http://…:8889/live/dji-webrtc

Ce qu'elle fait

Un régisseur de poche

Pensée pour être ouverte cinq minutes avant le direct, sur le poste qui sert de régie.

01

Une seule entrée RTMP

Caméra DJI ou relais Android : une URL d'entrée suffit. Plus de scan ni de forçage Bluetooth, l'app reste un pur pont local RTMP → WebRTC.

02

H.264 + Opus en une passe

La vidéo et le son sont réencodés ensemble dans le même ffmpeg. L'Opus est produit directement depuis la source, ce qui corrige le son dégradé de l'ancienne chaîne AAC intermédiaire.

03

MediaMTX embarqué

Le serveur est téléchargé dans le dossier de l'app, jamais pris dans le système : la machine peut changer, le comportement reste identique.

04

WebRTC seule sortie

HLS et la sortie RTMP ont été retirés : une page WHEP à ouvrir dans le navigateur, avec les médias en UDP pour réduire la latence au minimum.

05

État réel du flux

« Serveur lancé » ne veut pas dire « caméra connectée » : l'app interroge l'API locale et distingue les deux, avec le débit reçu, les codecs et le nombre de lecteurs.

06

Diagnostics lisibles

Port occupé, ffmpeg absent, transcodage plus lent que le temps réel : chaque panne arrive avec sa cause dans l'onglet Journaux.

Latence

Réglée pour le direct, pas pour l'archive

Chaque maillon est réglé à la main pour que l'image arrive au moniteur sans traîner : sortie GOP d'une seconde, aucun frame B, timestamps réécrits à l'arrivée et paquets écrits sans tampon.

  • Timestamps à l'horloge murale. Les flux caméra et relais arrivent avec des DTS répétés : ffmpeg les réécrit à la réception, audio et vidéo restent calés.
  • Keyframe toutes les secondes. Un lecteur qui rejoint accroche l'image tout de suite et peut couper proprement.
  • Zéro frame B, zéro lookahead. Le profil x264 zerolatency est poussé jusqu'au bout : pas de réordonnancement à la sortie.
  • Paquets écrits sans tampon. -flush_packets 1 pousse chaque frame vers MediaMTX dès qu'elle est encodée.
  • Opus à 160 kb/s, 48 kHz. L'audio est réencodé directement depuis la source et transporté tel quel par WebRTC, sans étape AAC intermédiaire. 
ffmpeg -flags low_delay -use_wallclock_as_timestamps 1 \
  -fflags +genpts -rtsp_transport tcp \
  -i rtsp://127.0.0.1:8554/live/dji \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -g 30 -keyint_min 30 -bf 0 -fps_mode cfr \
  -b:v 6M -maxrate 6M -bufsize 6M \
  -c:a libopus -b:a 160k -ar 48000 -ac 2 \
  -application audio -frame_duration 20 \
  -flush_packets 1 -f flv \
  rtmp://127.0.0.1:1935/live/dji-webrtc

Installation

Trois commandes, une fenêtre

Le paquet installe le binaire et son entrée de menu. Les outils annexes se récupèrent depuis l'application.

1 · Installer ffmpeg

L'encodage H.264 + Opus passe par ffmpeg. S'il est absent, l'app le signale dans les réglages et les journaux.

sudo apt install ffmpeg

2 · Installer le paquet

Le .deb contient l'application seule. Les dépendances GTK et WebKitGTK sont résolues par apt.

sudo apt install ./dji-caster_0.2.0_amd64.deb

macOS : dézippez l'archive universelle et glissez dji-caster.app dans Applications. L'app n'est pas signée : clic droit → Ouvrir au premier lancement.

3 · Lancer et connecter la source

Ouvrez « DJI Caster », installez MediaMTX depuis les réglages, puis saisissez l'URL d'entrée affichée dans DJI Relay (ou sur la caméra). Ouvrez l'URL WebRTC pour voir le direct.

dji-caster

Prérequis : Ubuntu 22.04+ / Debian 12+, ffmpeg, et une source qui pousse en RTMP (caméra DJI ou relais Android).
